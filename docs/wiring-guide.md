## 1. 到货先验货（10 分钟，先别上电）

按顺序做，任何一步不对就拍照留证：

1. **看外壳**：天线罩有没有裂、圆柱有没有变形
2. **手转电机**：手指轻推上半板，应该能**顺滑转动、没有卡顿和异响**（有滑环感的阻力是正常的）
3. **看 Type-C 座**：用手机手电筒照，座子有没有歪、引脚有没有脱焊
4. **看背面 BTB**：那个 24 pin 的小连接器是不是空的（空着才对）
5. **看有没有 `ATHEROS` 字样的模块**：那块是 WiFi 网卡，**别拆别碰**
6. **称重**：整机约 300–400 g，明显偏轻说明缺件

然后**只接供电**（先别接数据），看三件事：

- LED 亮不亮
- **上半板是否自己慢慢转**（默认 60 rpm，约 1 秒 1 圈）
- 转动时有没有异响

✅ 转了 = 电机、线圈取电、下板 MCU 都是好的，可以往下走。
❌ 不转 = 先别接数据，直接找卖家。

## 2. 认识 Type-C 上的 24 根针

雷达的 Type-C 母座里，有用的只有这几根（来自作者实测）：

| 针脚 | 信号 | 接到哪 |
|---|---|---|
| **A4 / A9 / B4 / B9** | VBUS 15V | 电源正极 |
| **A1 / A12 / B1 / B12** | GND | 电源负极 + 数据地 |
| **B6** | USB D+ | 电脑 USB 绿线 |
| **B7** | USB D− | 电脑 USB 白线 |
| **B2** | CAN_H | CANable CANH |
| **B3** | CAN_L | CANable CANL |
| A2 / A3 | RS485 A/B | 实测无数据，不用 |

> 为什么必须用测试板：Type-C 口同一时刻**只能插一个东西**。插电源就没了数据线，插数据线就没了 15V。测试板的作用是把母座、公头、排针三者并在一起，让电和数据同时进出。

## 3. 接线（零焊接，全程插拔）

```
┌─────────────┐   DC5.5    ┌──────────────────┐  Type-C  ┌────────┐
│ 15V 适配器  │───────────▶│ 板上 Type-C 母座 │           │        │
└─────────────┘  (¥2.30线) └──────────────────┘           │ 雷达   │
                            │ 测试板（¥8.50）  │  公头 ───▶│ Type-C │
┌─────────────┐   USB-A    │   2×12 排针      │           │  母座  │
│ 电脑 USB 口 │───────────▶│  B6 / B7 / GND   │           └────────┘
└─────────────┘  (¥5.45线) └──────────────────┘
```

### 3.1 电源这一路

```
15V 适配器 DC 头 → [DC母转C公线] → 测试板的 Type-C 母座
```

### 3.2 数据这一路（关键，别接错）

那根 USB 转杜邦线是 **USB-A 公头 + 4 个杜邦母头**，四个母头的颜色是：

| 线色 | 通常是 | 接到测试板 |
|---|---|---|
| 🔴 红 | +5V | ❌ **剪断或胶布包死，绝对不接** |
| ⚪ 白 | D− | **B7** |
| 🟢 绿 | D+ | **B6** |
| ⚫ 黑 | GND | **GND**（任一个 GND 针） |

> 🔥 **红色那根是这次唯一会烧东西的线。** 测试板上的 VBUS 针和雷达的 15V 是**直通**的，把 USB 红线插上去 = 把 15V 倒灌进电脑 USB 口。轻则烧口，重则烧主板。**先剪了它再动别的。**

### 3.3 CAN 这一路（有 CANable 才接）

| 测试板 | CANable 端子 |
|---|---|
| B2 | CANH |
| B3 | CANL |
| GND | GND |

杜邦母头插排针 → 另一头剪断剥 5 mm 铜 → 松开端子螺丝 → 插进去拧紧。

**CANable 上的 120Ω 拨码开关打到 ON**（总线两端各一个 120Ω，这里只有我们这一端，另一个在雷达里）。

## 4. 电脑侧：Ubuntu 里的准备（已经装好了）

虚拟机上已经完成，这里只是**确认**。开机后跑：

```bash

# 期望：ath6kl_usb / ath6kl_core / cfg80211 三行

# 期望：bdata.bin  fw-5.bin  fw.ram.bin

# 3) 插上雷达后，网卡出来没有
```

如果 `lsmod` 没有 ath6kl：

```bash
sudo modprobe ath6kl_usb
```

### 4.1 USB 直通（每次开虚拟机都要做一次）

VMware 菜单 → `虚拟机` → `可移动设备` → 找到 `AR6004` 或 `0cf3:1022` → `连接`。

或者一次性写进 `.vmx`（关机状态下改）：

```
usb.autoConnect.device0 = "vid:0x0cf3 pid:0x1022"
```

## 5. 上电，看它连上来

### 5.1 先看网卡

插上所有线、给 15V 之后，等 10 秒：

```bash
lsusb | grep -i 0cf3
# 期望：Bus 001 Device 00x: ID 0cf3:1022 Atheros Communications, Inc. AR6004

ip link | grep wlx
# 期望：wlx00037f2044d2: <BROADCAST,MULTICAST> mtu 1500 ...
```

**没出现 `wlx` 网卡** → 见第 9 节排错表第 1、2 条。

### 5.2 起 AP（让雷达连我们）

```bash
cd ~/work/dji-agras-radar
sudo ./setup/start_ap.sh
```

脚本会：停 NetworkManager → 给网卡配 `192.168.8.1/24` → 用 hostapd 起 SSID `radar_wifi` 的开放热点。

成功标志：

```bash
sudo iw dev            # 能看到 type AP
ip addr show wlx...    # 有 192.168.8.1/24
```

### 5.3 等雷达连上来

雷达的 zynq 上电后会自己找 `radar_wifi`（SSID 写死在 `/etc/dji.json` 里），连上后拿静态 IP `192.168.8.2`。

```bash
# 看有没有客户端连进来
sudo iw dev wlx00037f2044d2 station dump
# 期望：Station xx:xx:xx:xx:xx:xx (on wlx...)

# 直接 ping 雷达
ping -c 3 192.168.8.2
```

✅ `ping` 通 = 网络链路打通，最难的一关过了。

### 5.4 SSH 进雷达

```bash
ssh -p 107 -oHostKeyAlgorithms=+ssh-dss root@192.168.8.2
# 密码：root
```

进去后确认三件事：

```bash
ps | grep app.elf          # 业务进程在跑
ls /dev/uio*               # uio0~uio3 四个设备
ls /proc/$(pidof app.elf)/maps | head
```

## 6. 读出数据

### 6.1 顶面 4×4 阵面热图（不需要 CAN）

这是**唯一一条不需要电机转、不需要 CAN 就能出数据**的路。顶阵是电子扫描，上电就有。

```bash
# 1) 把工具传上去
scp -P 107 -oHostKeyAlgorithms=+ssh-dss radar_client/radar_streamer root@192.168.8.2:/tmp/

# 2) 在雷达上跑（PID 换成 app.elf 的）
PID=$(ssh -p 107 -oHostKeyAlgorithms=+ssh-dss root@192.168.8.2 'pidof app.elf')
ssh -p 107 -oHostKeyAlgorithms=+ssh-dss root@192.168.8.2 "/tmp/radar_streamer top $PID 9876"
```

然后在 Ubuntu 里把 9876 转发出来看，或者用我们的 Web 端接。

> 顶阵数据**不走网络**（作者穷举过所有发送函数，顶阵没有上报通道），只能从 `/proc/PID/mem` 抠。

### 6.2 侧面 12×6 点云（需要 CAN + 电机转起来）

**这是关键一步**：不转 = 没有数据。编码器是物理线接进 FPGA 的，软件模拟不了。

```bash
# 1) 起 CAN
sudo slcand -o -c -s8 /dev/ttyACM0 can0     # -s8 = 1 Mbit
sudo ip link set can0 up

# 2) 看雷达有没有在发
candump can0
# 期望：一堆 0A3 的帧，形如 55 39 04 25 18 78 10 00 ...
```

看到 `0A3` 的帧 = CAN 通了。

```bash
# 3) 让电机转起来（假飞控）
cd ~/work/dji-agras-radar/radar_client
source ../venv/bin/activate
python radar_min_client.py --can-bridge can0 --send-motor-start --send-data-start-type 0 --plot
```

参数说明：

- `--can-bridge can0`：走真 CAN（**不能和 `--sim-esc` 同时用**，两者互斥）
- `--send-motor-start`：发使能命令（`0x1E/0x09`）
- `--send-data-start-type 0`：开始要数据

### 6.3 看真数据

```bash
python radar_viewer.py --deploy
```

它会在雷达上拉起两个 streamer：

- `9876` = 顶阵热图（8908 B/帧）
- `9877` = 侧面点云（60632 B/帧，360 扇区 × 160 B）

## 8. 三个「必须」和一个「绝对不要」

**必须**

1. 电机**真的转起来**，侧面点云才会刷
2. `--can-bridge` 和 `--sim-esc` **只能二选一**，真机用前者
3. 雷达的 `192.168.8.2` 是**静态 IP**，不需要 DHCP

**绝对不要**

- ❌ 把 USB 转杜邦线的**红线**插到测试板 VBUS（15V 倒灌烧主板）
- ❌ 在雷达不带外壳时开高转速（作者 1800 rpm 时雷达飞出去过）
- ❌ 碰 `normal.bin` / 刷固件（`antirollback=1`，刷错无公开救砖法）
- ❌ 拆那块 `ATHEROS` 模块（唯一的无线通道）

## 9. 排错表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `lsusb` 看不到 `0cf3:1022` | USB 没通 / 线接错 / 15V 没供上 | 先量 15V；再查 B6/B7 有没有插反；换 USB 口 |
| 出现设备但没 `wlx` 网卡 | 固件没加载 | `dmesg \| tail -30` 看 `ath6kl` 报错；确认三个固件文件在 |
| 有网卡，AP 起不来 | NetworkManager 抢网卡 | `sudo airmon-ng check kill`，或 `sudo systemctl stop NetworkManager` |
| AP 起来了但扫不到 `radar_wifi` | `ignore_broadcast_ssid` 没注释 | 改 `setup/hostapd.conf`，把那行注释掉 |
| 电脑搜到 AP 但连不上 | 没 DHCP（正常） | **不用管**，雷达用静态 IP |
| `ping 192.168.8.2` 不通 | 雷达没连上 / zynq 没启动完 | 等 30 秒再试；`sudo iw dev wlx... station dump` 看有没有客户端 |
| SSH 报 `no matching host key type` | dropbear 只给 ssh-dss | 加 `-oHostKeyAlgorithms=+ssh-dss` |
| `candump` 什么都没有 | bitrate 错 / 线接反 / 终端电阻没开 | 确认 1 Mbit；CANH/CANL 对调试试；拨码 ON |
| 有 CAN 帧但没点云 | 电机没转 / 编码器没信号 | 先确认上半板在转；`radar_min_client.py --send-motor-start` |
| 点云一直是空的 | 编码器没被采信 | 看 `dmesg` 有没有 `[FMCT] wrong sample key`；这是软件修不了的硬约束 |
| `--sim-esc` 报 not allowed | 和 `--can-bridge` 互斥 | 真机去掉 `--sim-esc` |

## 11. 两个「看起来没问题、实际会卡死」的坑

### 11.1 DC 头 5.5×2.1 还是 5.5×2.5（最常见）

DC 圆头有两个尺寸在流通：

| 型号 | 外径 | 内孔直径 | 谁在用 |
|---|---|---|---|
| **5.5×2.1** | 5.5 mm | **2.1 mm** | 路由器、小家电、绝大多数 12V/15V 适配器 |
| 5.5×2.5 | 5.5 mm | **2.5 mm** | 部分大功率适配器、笔记本、工控 |

**问题**：电源送的 DC 头如果和线的 DC 母座不配——

- 电源是 **2.5**、线是 **2.1** → **插不进去**（针太粗）
- 电源是 **2.1**、线是 **2.5** → 能插，但**内孔松、接触不良**，一碰就断电重启

**怎么破**：

1. 京东那单写的是「**赠两个转接头**」——那两个很可能就是 2.1↔2.5 的转换头，**先找到它们别扔**
2. 核对电源商品页有没有写「5.5×2.1」或「5521」
3. 实在不配，淘宝单买一个「DC 5.5×2.5 公转 5.5×2.1 母 转换头」，2 元

### 11.2 24P 测试板必须是「纯转接板」

市面上有两种叫「Type-C 测试板」的东西：

| 类型 | 特征 | 能用吗 |
|---|---|---|
| **纯转接板** | 板上**只有焊盘和走线**，没有芯片、没有电容电阻阵列 | ✅ 要这个 |
| 带电路的板 | 板上有 IC、TVS、电平转换 | ❌ VBUS 可能不过，或者过了会掉压 |

**怎么认**：拿到手看板子——**干干净净只有铜箔走线和丝印**就是对的；有黑色小方块 IC 就是错的。

**验证方法（不需要万用表）**：

```
只接电源（先别接 USB 数据线）：
  15V 适配器 → DC转C线 → 板母座
  板公头 → 插雷达
  ↓
看雷达转不转 + LED 亮不亮
```

转了 = VBUS 通、板子是直通的、极性也对。**这一步过了再接数据线。**

### 11.3 到货上电顺序（防烧，务必按这个来）

```
第 1 步：断电状态下把所有线接好
        （电源线插板的母座、USB 杜邦线插排针 —— 红线已剪）
第 2 步：USB-A 插电脑
第 3 步：最后才给 15V 上电
第 4 步：等 10 秒，看 lsusb 有没有 0cf3:1022

❌ 不要反过来（先上电再插 USB）
❌ 不要把 USB 红线接到 VBUS
```

### 11.4 如果白/绿接反了会怎样

USB 的 D+ / D- 接反，多数情况下**枚举不出来**（有时候能出「未知设备」）。

判断：`lsusb` 什么都没有，但电脑有「设备接入」提示音 → 大概率是 D+/D- 反了。

**处理**：断电，把白绿两根在排针上对调（B6 ↔ B7），再试。

> 这也是为什么建议用杜邦线插排针而不是焊死——反了能立刻换。

### 11.5 这根 ¥2.30 的 DC 转 C 线够不够（功率核算）

商品页写「0.3 平方纯铜线芯，**36W 以下用**」。而 15V × 3A = 45W，看起来超了。

**先算雷达实际要多少电**（没有官方数据，按器件估）：

| 部件 | 估计功耗 |
|---|---|
| Zynq XC7Z020（PS + PL） | 2–3 W |
| AFE5401 ×4 通道 + 射频前端 | 5–8 W |
| 旋转电机（900 rpm 空载） | 3–6 W |
| AR1021x WiFi | 1–2 W |
| **合计** | **约 12–18 W ≈ 15V 下 0.8–1.2 A** |

**稳态远低于 36W**，这根线够用。电源选 3A 是余量，不是实际消耗。

**真正的风险在启动瞬间**：电机堵转电流可能是稳态的 3–5 倍，短时冲到 3–5A，0.3 mm² 的线上会有明显压降。

**怎么判断是不是压降问题**：

- 雷达转一下就停、然后反复重启
- LED 闪一下就灭
- 一加转速（60 → 900 rpm）就掉线

出现这些，就是线太细或电源带不动。

**备用方案（推荐，¥2–3）**：

搜「**DC 5.5×2.1 母 转 Type-C 公 转接头**」——要**硬质转接头**不是线。

内部是铜片压接，没有线芯瓶颈，过 5A 没问题。体积小，直接插在电源和 24P 板之间。

> 不用现在换线。先用手上这根，出现上面的症状再加转接头。
